Лабораторная работа N3 Иерархия Классов
Вариант F Охранная система

Разработать приложение, позволяющее описывать состояние охранной системы, состоящей из стационарных и мобильных компонент, в которые должны входить информации о его компонентах и среде функционирования.

Описатель среды представляет собой клетчатый двумерный план помещения, включающий препятствия, компоненты охранной системы и нарушителей.


Каждый компонент представляет собой модульную платформу, для которой определены: координаты, строка описания, уровень энергообеспечения, количество слотов для подключения модулей. Для каждого модуля определен уровень его энергопотребления или энергообеспечения (в активном и пассивном режимах, если они предусмотрены), состояние (включен/выключен), количество слотов, которое он занимает.
Определены следующие типы платформ^1:
- стационарные (не могут изменять местоположение, связаны с ИИ напрямую)
- мобильные (имеют возможность изменять свое местоположение, характеризуются скоростью передвижения)

Определены следующие типы модулей:
- сетевой
- датчик
- вооружение

Модули могут быть установлены на любой тип платформ.

Сетевой модуль позволяет поддерживать несколько сенсоров связи с определенным числом компонент, как непосредственно, так и через промежуточные узлы (промежуточный узел расходует два сеанса), для сетевого модуля определен: радиус действия, таблица^2 активных сеансов и таблица коммутации. Если у мобильного робота отсутствует связь с ИИ, то становится неработоспособным.

Датчики позволяют получать информацию об окружающем пространстве (наличие соседних компонент, нарушителей и местоположение самой платформы в пространстве), для датчика определен: радиус действия, тип (рентгеновский, оптический).

Вооружение позволяет обезвредить нарушителя, характеризуются: радиусом действия, временем зарядки (при выпуске находится в активном режиме энергопотребления).

Нарушитель перемещается по помещению случайным образом либо пытается убежать от охранного устройства в зависимости от алгоритма поведения.

## Обеспечить также выполнение следующих операций:
- Для описателя среды:
  - получение/изменение размеров игрового поля
  - получение/изменение типа клетки с заданной координатой
- Для компонента (платформы):
  - установить/удалить модуль
- Для мобильного робота:
    - перспективы робота в заданном направлении
- Для модуля:
    - включить/выключить (проверяется достаточность энергообеспечения)
- Для датчика:
    - получить информацию о среде, в соответствии с типом датчика
- Для вооружения:
    - обезвредить нарушителя
	- переключиться в/из режима зарядки	
- Для сетевого модуля:
    - получить список непосредственно доступных партнеров
    - запросить/выдать список доступных партнеров у соседних модулей
    - установить непосредственно соединение или канал связи
- Для нарушителя:
    - изменять местоположение в соответствии с алгоритмом
- Для алгоритма поведения нарушителя:
    - вернуть следующую координату для перемещения нарушителя
- Для ИИ:
    - обезвредить всех нарушителей^3
	
	
	
^1 - Расширяемый класс - платформа. Необходимо предусмотреть возможность переопределения основных операций платформы в новом классе - наследкие (например, квантовая плафтормаб которая связана с другой квантовой плафтормой и может в любой момент поменяться с ней местами)
^2 - Шаблонный класс - вектор
^3 - Указанную операцию реализовать в многопоточном режиме. Каждая группа платформ/атчиков обрабатывается в отдельном потоке.
